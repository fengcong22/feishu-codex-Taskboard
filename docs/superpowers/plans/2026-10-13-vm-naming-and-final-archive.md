# VM 阶段命名与成片归档

本文件记录 2026-10-13 的配置与规划阶段。文中关于生产流程尚未接通的状态已由 [2026-10-15 VM 审核工作流计划](2026-10-15-vm-review-workflow.md) 更新；当前交付状态见 [VM / PMO 离线联调](../vm-pmo-offline-integration.md)。

当时保存配置不启用 VM 执行，也不改 Auto-cut-lite 的生产链路。

## 配置合同

用户进一步明确：三个输出共用同一个名称主体，只有阶段后缀不同。`fields.namingFieldId` 是唯一可空的 PMO 文本或公式命名绑定；移除阶段和归档里的重复命名字段。一处字段选择控制整个学科的 VM 命名，留空表示尚未绑定，不读取或猜测其他字段。初稿名称固定为 `<字段结果>_初稿.mp4`；审核修改为 `<字段结果>_第N稿.mp4`，N 从 1 开始；最终成片为 `<字段结果>.mp4`。同一审核轮次的失败重试、上传重试复用编号，不根据目录扫描或附件顺序推测编号。

顶层新增 `finalArchive`：

```ts
{
  enabled: boolean;
  statusFieldId: string | null;
  triggerOptionId: string | null;
  pathSource: "manual" | "pmo_field";
  directoryPath: string | null;
  pathFieldId: string | null;
}
```

触发支持单选进入或多选新增所配置选项，持续命中不重复归档。用户要求直接给出具体目录，移除课程目录命名字段；NAS 目标规则为 `<指定目录>\<统一命名字段结果>.mp4`，不追加课程名或 `00成片`。路径来源为手动输入或指定 PMO 文本/公式字段，字段模式按精确字段 ID 读取有效文本，失败不回退到手动路径。两种来源均校验 Windows 绝对盘符或完整 UNC，拒绝相对路径、穿越和设备路径。PMO 目录只用于归档，不允许指定工作区、命令或 prompt。命名规划对所有输出使用同一固定主体预算，预留最大合法审核轮次的最长后缀，超长主体在同一位置截短；完整文件名不超过 180 个 UTF-16 单元，不拆分代理对并保留后缀。

旧草稿缺少新增配置时补空绑定和 disabled 归档，只在显式保存时写入，不改变 GET 的 revision。已有独立命名绑定若一致则合并，若冲突则不猜选并提示重新选择；规范输出和显式保存只保留统一字段。旧根路径或课程绑定只读转换时清空新目录绑定并返回 `legacyArchivePathNeedsReview` 提示，保留触发配置，要求重新确认具体目录；不能把旧根目录直接当作最终目录。未知配置键和错误类型拒绝；实时 metadata 必须唯一且类型匹配。

## 实施与验证

1. 后端草稿：扩展 canonical schema、旧数据默认值、路径及文本/公式 metadata 校验。以真实 SQLite fixture 覆盖保存、重启、无 GET 写入、错误路径/字段、旧迁移及门禁。
2. 前端：基础与执行页放唯一的视频主体命名字段，阶段保留后缀说明，存储页放 NAS 归档触发、路径来源及对应输入并引用统一名称预览。保持现有四页及冻结按钮；覆盖切页、保存、字段过滤、模式切换保留输入和触发字段切换清空选项。区分旧/未知配置项与字段绑定错误，成功恢复只清所属配置错误，失败保留提示。
3. 命名/归档规划：实现无文件写入的受控规则模块。用精确字段 ID读取值，校验文本/公式结果、Windows 文件名、审核编号；复用绝对路径及映射盘解析能力但不追加课程子目录。归档只接受同记录已确认 PMO 交付的明确 MP4 身份与 SHA，缺失则阻断，不按 mtime 或附件列表取“最新”。单元测试验证这些边界。
4. 文档：记录配置项和当时的已实现范围；后续 VM/PMO v2 接入计划负责更新生产编排、MP4 交付队列与 NAS 发布状态。
5. 运行相关后端和 UI 测试、类型检查、`build:web`、diff 检查；只读代码评审。安全重启本机服务后检查健康，在实际配置页验证新增字段及滚动，不保存生产配置做测试。

本计划形成时 NAS 发布仍待接入。当前 worker 的运行边界和验收状态见 [VM / PMO 离线联调](../vm-pmo-offline-integration.md)；preview 声明仍不能单独授予生产执行资格。
