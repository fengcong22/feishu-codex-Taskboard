# 飞书任务标题字段回退设计

## 目标

为飞书多维表格触发的 Taskboard 任务提供稳定、易读的卡片标题。标题按以下顺序取值：

1. `视频名称`
2. `集合文档`
3. 记录 ID

标题统一使用 `[待剪辑] <名称>` 格式；记录 ID 始终保留在任务描述中用于精确回查。

## 范围

- 仅影响后续由 Bridge 新建的任务。
- 不修改飞书 Base 中的记录。
- 不自动重命名已经存在的 Taskboard 任务。
- 不改变触发字段、项目包路由、手动启动模式或事件去重逻辑。

## 数据流与配置

目标表的配置增加标题字段 ID 映射：`视频名称` 使用 `fldHoU4xyR`，`集合文档` 使用 `fldyganryv`。`drive.file.bitable_record_changed_v1` 通常只携带本次发生变化的字段，因此触发规则命中后，Bridge 使用同一 PMO 应用的官方 SDK 读取当前整条记录，再生成 `recordTitle`：先取去空白后的“视频名称”，为空再取“集合文档”，两者都为空时保留空值，由任务负载层回退到记录 ID。

字段值需要兼容飞书文本字段常见的字符串、JSON 编码字符串和带 `text`/`name`/`value`/`label` 属性的对象形式。空白值视为空。

## 任务负载

`buildTaskPayload` 继续负责格式化标题：`[待剪辑] ${recordTitle || recordId}`。描述中的记录 ID、触发字段变化和项目包信息保持现有格式。

## 错误与兼容性

- 事件未携带标题字段时，按旧行为回退到记录 ID。
- 标题字段不存在、值无法解析或记录查询失败时，不阻塞任务创建，只走下一级回退。
- 当前记录查询最多等待 5 秒；超时后立即按记录 ID 建任务，避免阻塞后续事件。
- 现有测试事件只提供 `recordTitle` 或不提供标题字段时，测试结果保持兼容。

## 验证

- 增加规范化测试：视频名称优先、视频名称为空时使用集合文档、两者为空时保留空标题供负载层回退。
- 增加任务负载测试：标题按三种情况分别生成。
- 运行完整 `npm test`，并用一次真实飞书事件验证新任务标题。
