# 学科公共剪辑模式

用户已在对话中确认本方案并授权开始实现。

所有学科的配置页面在三阶段之前提供一个公共「通用执行设置」区，包含「剪辑模式：自动 / 手动」及现有并发设置。单阶段和三阶段共享 `execution.mode`，不增加阶段级模式。修改仍通过保存草稿、显式启用发布活动快照；模式适用于之后登记的任务，不批量修改历史任务或运行。

从 Base 元数据首次创建的学科草稿默认 `automatic`，仍保持草稿。已有学科的模式在刷新、重新导入或恢复时沿用持久化值。历史数据缺字段和共享配置缺省模式继续保守回退 `manual`；共享配置中显式指定的模式仍按既有导入规则处理。

机器总闸继续由启动环境变量控制且默认关闭。只读 `/api/meta` 将服务器实际采用的布尔策略作为 `capabilities.automaticExecution` 返回，前端显示开启、关闭或状态未知。该显示不提供修改机器策略的入口；关闭时说明学科即使选择自动，也需要人工启动。上传模式保持独立。

不修改 Bridge 事件筛选、loopback 地址、来源认证、白名单、模拟事件隔离或生产配置。不重启正在运行的生产服务。使用独立临时数据库、测试表 metadata 和受控测试执行器验证。

验收：新学科默认自动草稿；已有手动和自动学科刷新/恢复后不变；单阶段和三阶段各显示唯一公共控件；切换两种模式并保存后阶段和上传配置保持；草稿未启用不更新活动快照；实际总闸返回正确且关闭/未知提示准确；模拟来源与总闸关闭均不能启动。通过完整 `npm test`、示例工作流验证和独立代码评审，提交功能分支供推送/合并。
