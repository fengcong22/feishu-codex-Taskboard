# 课程目录、飞书回写与学科配置改版设计

日期：2026-09-17。代码基线：`ec95499`。状态：已实现并通过自动化回归，待测试表、示例项目和专用 NAS 目录联调。

本文是功能设计，不替代仓库唯一运行规范 `AGENTS.md`。目录交付与受控飞书回写已随实现、测试和运行说明交付；真实飞书和 NAS 联调仍需使用测试表、测试记录及专用可写目录。

## 1. 交付范围与决策

本次按一个版本交付，分为目录交付、飞书回写、配置界面三个可独立评审的部分。

| 编号 | 已确定行为 |
| --- | --- |
| R01 | 每个学科配置一个上传总路径，代替三个阶段的上传目标路径。支持可访问的映射盘和 UNC；本地目录也可用于实际上传。 |
| R02 | 从已有文本字段或结果为单一文本的公式字段读取课程文件夹名称；可以复用 ZIP 命名字段，也可以单独选择。 |

| R04 | 初稿、初审修改、终审修改分别使用 `01初稿`、`02初审`、`03终审`，只在对应 ZIP 写入时创建。 |
| R05 | 真正进入处理中，以及本次全部 ZIP 上传成功时，分别按阶段回写指定的已有单选字段和已有选项。 |
| R06 | 首个 ZIP 上传成功后，把课程目录路径写入指定的已有可写文本字段；不含阶段目录和 ZIP 文件名。 |
| R07 | NAS 回写路径保留共享名及后续目录，只去除服务器前缀；普通本地盘只去除盘符。例如分别为 `学科实拍素材临时传输\【--剪映草稿--】\课程001`、`目录\课程001`。 |
| R08 | 独立单选条件触发创建 `00成片`，不创建剪辑任务。仅创建该目录不回写课程路径。 |
| R09 | 取消学科“流程名称与说明”及全局流程标签编辑，使用系统固定名称与说明。 |
| R10 | 学科配置按五个分区组织；独占资源配置移到 Auto-Cut 包管理。 |
| R11 | 补齐草稿保护、明确应用状态、关闭阶段的校验、字段刷新、路径预览、错误定位和独立重试。 |

不增加通用“飞书状态映射看板列”、历史记录批量补跑、自动覆盖同名 ZIP、自动改名旧目录或从单元格读取命令的能力。

## 2. 用户配置与字段含义

### 2.1 目录配置

学科的“存储与目录”提供：上传开关、上传总路径、课程命名来源、目录预览及检查。总路径由本机配置界面填写，不从飞书记录中读取。

新版配置以 `delivery.version = 1` 标识，配置尚未应用时不产生新行为。上传开关独立于处理中回写和额外触发：只启用处理中回写时无需课程目录；上传或 `00成片` 任一启用时才要求总路径、命名字段及课程绑定。启用“全部 ZIP 上传成功”或课程路径回写必须同时启用上传，否则应用时定位配置错误。关闭上传不改变已经冻结的任务/上传批次。

课程命名默认“复用 ZIP 命名字段”，也可改为“单独选择字段”。两者分别控制文件夹名称和 ZIP 产物名称，改动文件夹规则不隐式改名 ZIP。

只允许文本字段和返回单一文本的公式字段。保存字段 ID 和名称快照，执行时按 ID 重新确认字段类型。公式读取的是计算后的值，不执行公式字符串，也不把数组、多个值、错误值或空值强行转成文件夹名。现有命名逻辑的其他类型兼容不得悄悄扩大目录命名范围。

### 2.2 阶段状态回写

每个启用阶段单独配置两个规则组：“进入处理中”“全部 ZIP 上传成功”。每组可关闭或添加多行，每行选择一个已有单选字段和该字段中的一个已有选项。例如：

| 阶段 | 时机 | 已有字段 | 已有选项（示例） |
| --- | --- | --- | --- |
| 初稿 | 进入处理中 | 当前状态 | 自动剪辑中 |
| 初稿 | 全部 ZIP 上传成功 | 当前状态 | 初稿待检查 |
| 初审修改 | 进入处理中 | 修改状态 | 初审修改中 |
| 初审修改 | 全部 ZIP 上传成功 | 修改状态 | 初审待检查 |
| 终审修改 | 全部 ZIP 上传成功 | 终审状态 | 终审待检查 |

示例不代表要创建这些字段或选项。界面只展示实际加载到的已有字段与选项；更换字段后，失效选项清空为“待选择”，不能按选项顺序自动分配。一个规则组内同一字段只能出现一次。

任务创建时冻结规则快照。后续修改学科配置只影响新任务；若原字段或选项已被删除、类型已变，旧任务显示配置失效，不创建替代字段或选项。

### 2.3 课程目录路径回写

全学科配置一个已有可写文本字段。该规则独立于各阶段状态规则；仅有公式、查找引用或只读文本样式字段时不能作为写入目标。

同一课程首次成功上传任意一个 ZIP 后，登记一次路径回写操作。首个 ZIP 上传事务固定本次目标字段和目录值；后续阶段复用，不因为改配置而反复写入其他字段。若该时刻没有启用路径回写，不自动补写历史课程；页面明确此语义。

回写失败只重试回写。即使文本已被人工修改，也不能因为后续 ZIP 成功而自动覆盖；操作显示冲突并允许核对后定向重试。

### 2.4 额外触发

“额外触发”独立配置启用开关、已有单选字段和已有选项。只在从其他值进入指定选项时，申请创建课程目录下的 `00成片`。选项保持不变不重复申请；退出该选项不删除目录。启动时不扫描历史记录。

可在没有任何 ZIP 前触发。可在所有剪辑阶段关闭时使用，但必须具备有效的表、总路径和课程命名来源。此操作不需要开启“允许本机自动剪辑”，因为它不启动剪辑；必须单独通过已应用的额外触发配置授权。

### 2.5 三个阶段的素材来源不合并

初稿、初审修改、终审修改继续各自保存完整的素材配置，不能被一个学科级“素材字段”替代。三个阶段可以选择相同字段，也可以完全不同；更改一个阶段不会连带修改另两个阶段。

| 每个阶段的配置 | 可选来源与显示规则 |
| --- | --- |
| 视频素材来源 | “文档目录”并填写该阶段的视频目录标题，或“Base 附件字段”并选择已有附件字段 |
| 音频素材来源 | “视频原音”、 “文档目录”或“Base 附件字段”；选择外部音频时再显示对应目录标题/附件字段及允许时长误差 |
| 剪辑意见来源 | 保留现有每阶段独立配置；当前契约为文档目录及该阶段的意见目录标题 |
| 触发选项 | 从阶段触发单选字段的已有选项中独立选择 |
| ZIP 命名后缀 | 每阶段独立保留；ZIP 目标目录输入取消，由上传总路径和固定阶段目录计算 |

因此，“素材与阶段”顶部只放共同的阶段触发字段及必要说明，不再出现会让人误解为共用来源的“素材字段”。每个阶段使用可折叠编辑区；摘要同时显示视频、音频、意见来源和触发选项。停用阶段收起但保留这些值，应用时不校验停用阶段的业务必填项。视频原音模式不显示无意义的音频目录、附件字段或时长误差控件。

## 2.6 Auto-Cut-Lite 协议保留门槛

本次只扩展 Taskboard 的目录交付与飞书回写层，不改 Auto-Cut-Lite 的运行协议。每次受控阶段运行仍生成并校验既有的 `source-manifest` schema v1、`execution_input` schema v1、环境变量、运行命令与结果/回执哈希；不能因为前端重排或目录新功能重命名、删除、合并或向 manifest 增加未协商字段。

| 协议面 | 必须保持的现有含义 |
| --- | --- |
| manifest `binding` | `task_id`、`run_id`、`subject_key`、`config_version`、`stage_id`、`event_id` |
| manifest `record` / `document` | Base、表、记录标识；文档字段和唯一的 Docx/Wiki 链接 |
| manifest `sources.video` | 每阶段独立的文档目录标题或 Base 附件字段 |
| manifest `sources.review` | 每阶段独立的文档目录标题；当前契约不扩大为 Base 文本字段 |
| manifest `sources.audio` | `video_original`，或 `replace_original` 加来源和 `duration_tolerance_seconds` |
| execution input | `schema_version: 1` 及经过现有规则清洗的 `artifact_name` |
| runner 调用 | `review-document-run` 的既有参数、`CODEX_AUTOCUT_*` 环境变量、manifest SHA-256 与结果/回执核对 |

上传总路径、课程绑定、阶段目录、回写规则和 NAS 路径不进入上述 manifest，也不能由飞书单元格传给 Auto-Cut-Lite。它们只在 Taskboard 的受控交付层使用。

当前 `stageSnapshot.artifactTargetPath` 是 Taskboard 上传队列使用的已有字段，虽不属于 manifest，但不能直接删除。新任务在首次课程绑定成功时计算相应阶段的绝对路径并冻结到该阶段快照，例如 `W:\根目录\课程001\01初稿`；这不创建文件夹。旧任务继续使用它们已经冻结的绝对路径。界面移除的是可编辑输入，不是任务协议字段，直到新派生路径已通过兼容测试前不得移除读取逻辑。

Auto-Cut-Lite 本次运行的 `packageZipPath` 也不是这个阶段上传目标。它继续位于受控本机 ZIP 来源根下，供 `review-document-run`、result、receipt、artifact report 和哈希校验使用；只有产物通过这些校验并登记为 Taskboard artifact 后，上传 worker 才从该 artifact 的存储内容发布到 `stageSnapshot.artifactTargetPath`。因此，新 NAS 目录不得替换 `packageZipPath`、`CODEX_AUTOCUT_PACKAGE_ZIP_PATH` 或包的 `zipSourceDirectory`。后者是本机 ZIP 来源根，并不是三个阶段的视频、意见或音频来源。

任何未来想删除或改名的协议字段，必须先给出“字段、当前消费者、迁移策略、旧运行行为、回归样本”清单，经明确确认后才可实施。不能把“界面不显示”当作可以删除持久化字段、历史快照或 Auto-Cut-Lite 输入的依据。

## 3. 目录绑定、创建和路径表示

### 3.1 绑定时机与持久化

以 `(baseToken, tableId, recordId)` 为唯一课程身份。对于启用了上传或额外目录触发的配置，首次可信阶段进入事件或可信 `00成片` 触发事件，到达 Taskboard 并校验命名值成功后，事务性地保存课程绑定。此时不创建课程目录或阶段目录。仅状态回写的任务无需绑定；已有绑定的后续事件直接复用，不因当前命名字段被改名或变空而重新求值。

绑定保存原命名字段 ID、读取值、规范化文件夹名、配置版本、实际根路径、可解析的 UNC 根路径、课程完整路径及课程显示路径。映射盘可见性依赖服务运行身份；每次文件操作必须确认仍映射到绑定的共享位置，不能在 `W:` 被重新映射后写入另一个 NAS。

课程名或根路径后来改变，只用于尚未绑定的新课程。旧课程继续使用首次绑定的文件夹。目录不可访问时显示故障，不自动切换新根目录或重新绑定。重命名和迁移旧课程目录不在本次范围内。

多个学科配置如指向同一记录，复用同一课程绑定；新配置与绑定不一致时展示原绑定事实。不同记录不能悄悄复用同一路径：规范化后的课程路径设唯一约束；同名冲突要求调整命名字段后再处理未绑定记录。

网络目录唯一键使用解析后的规范 UNC 位置，不使用用户输入盘符：`W:`、另一个映射盘和直接 UNC 指向同一目录时必须碰撞。本地目录使用规范卷位置和路径；Windows 比较规则统一处理大小写、分隔符与尾部分隔符。实际访问路径另存。服务器别名/DFS 等不能可靠解析为同一物理后端时需显式阻断或限制配置为同一规范共享入口，不宣称字符串规范化能识别所有 NAS 别名。

绑定失败不创建阶段任务或文件操作成功记录。事件进入可见失败/重试队列；不能创建一个以后随机选目录的任务。模拟事件不建立生产绑定。

### 3.2 文件夹按需出现

```text
已存在的上传总目录
└─ 课程001                      首次 ZIP 写入或 00成片 触发时创建
   ├─ 00成片                    仅额外触发命中时创建
   ├─ 01初稿                    仅初稿 ZIP 写入时创建
   ├─ 02初审                    仅初审修改 ZIP 写入时创建
   └─ 03终审                    仅终审修改 ZIP 写入时创建
```

总目录必须已经存在；应用不能因总路径输错而创建另一棵根目录。目录已经存在时，检查是安全目录后视为成功。课程目录首次已存在但没有绑定时允许采用无冲突的普通目录，不接管其中已有同名不同内容文件。写入失败留下的空目录保留供重试，不能自动递归清理。

目录名做确定性的 Windows 单段名称校验：拒绝空值、`.`、`..`、路径分隔符、设备名、非法字符、末尾空格/句点及超长名称。只修剪外围普通空白，不能静默替换多个非法值为同一个名称。拼接后再次验证目录包含关系、解析链接和重解析点，防止越过绑定根目录；外部参与者并发替换路径仍属于需要平台测试的边界。

### 3.3 三种路径不可混用

| 用途 | 示例 |
| --- | --- |
| 本机实际上传完整路径 | `W:\【--剪映草稿--】\课程001\01初稿\课程001_初稿.zip` |
| 同一位置的完整 UNC 路径 | `\\nas-server\学科实拍素材临时传输\【--剪映草稿--】\课程001\01初稿\课程001_初稿.zip` |
| NAS 的飞书文本字段课程目录值 | `学科实拍素材临时传输\【--剪映草稿--】\课程001` |
| 本地上传完整路径 | `D:\目录\课程001\01初稿\课程001_初稿.zip` |
| 本地盘的飞书文本字段课程目录值 | `目录\课程001` |

映射盘先解析为 UNC，再只移除 `\\服务器\`，保留共享名。不能直接对 `W:\` 做截断，也不能去除 UNC 的整个共享根。映射到共享子目录的盘符同样保留所有上级共享目录。输入 UNC 时按同样规则处理。

纯本地磁盘同时支持上传和路径回写，只去掉开头盘符及根分隔符，例如 `D:\目录\课程001` → `目录\课程001`，不添加共享名前缀。必须通过系统盘类型区分本地盘与网络映射盘；网络映射断开或解析失败时报告错误，不能误当本地盘并丢掉共享名。此规则已由用户在本轮明确确认。

回写值是供操作人员辨认的纯文本路径，不承诺飞书内单击即可打开资源管理器。完整服务器位置仅用于本机操作和必要的本机诊断；不写入飞书文本字段。

### 3.4 ZIP 成功标准

当前 Auto-Cut-Lite 协议每个 run 只绑定一个精确 `packageZipPath`，并只接受与其完全一致的 result、receipt 和 artifact report。该唯一 ZIP 通过验证、登记并成功上传才算该 run 的阶段交付完成；没有 ZIP、第二个 ZIP、目录扫描发现的 ZIP、失败 ZIP 或路径不一致的 ZIP 都不能判定成功。未来若要一个 run 交付多个 ZIP，必须先单独升级并确认运行、数据库和 Auto-Cut-Lite 协议。

每个 ZIP 以完整目标文件成功发布且内容哈希一致为成功；只创建目录、开始复制、写入临时文件或任务剪辑结束都不算成功。目标同名且同哈希视为成功；同名不同哈希报冲突，不覆盖、不自动附加版本号。

沿用安全的临时文件发布协议，但必须在测试 NAS 验证现有硬链接无覆盖发布是否受支持。仅测试 `mkdir` 成功不能证明 ZIP 发布可行。若不支持，发布前实现并验证同等“不覆盖/无半文件成功”的替代协议，或明确阻断该目标；禁止回退为覆盖式复制。

数据库记录成功时同时保存实际完整发布路径、课程绑定 ID、run ID，并事务性登记对应回写操作。上传 worker 从已登记的受验证 Taskboard artifact 读取内容，其 provenance 仍对应已校验的 `packageZipPath`；文件已发布但数据库未提交时，重试按哈希恢复，不重新覆盖文件，也不重新扫描或读取 Lite 的原输出路径。

## 4. 执行时机、可靠回写和反馈控制

### 4.1 两条受控链路

```text
飞书 SDK 事件 → Bridge 筛选/标准化/去重 → Taskboard 登记可信任务或目录操作
                                             ↓
                                  执行 / ZIP 上传 / 创建目录
                                             ↓
                                  同事务登记回写待办
                                             ↓
                               Taskboard 回写 worker
                                             ↓
                     带本机 secret 的 Bridge 专用回写接口 → 飞书
```

Bridge 保管飞书凭据，Taskboard 决定真实执行/上传时机并持久化回写待办。Bridge 不启动 Codex，不写 NAS；Taskboard 不复制飞书应用密钥。两端仍只绑定 `127.0.0.1`，复用本机专用来源鉴权边界。

“进入处理中”必须与真实受控执行启动及持久化运行标识关联。按钮点击、预约、等待资源、普通任务手工拖列，均不生成回写。运行启动失败前不回写“自动剪辑中”。受控手动启动和符合本机开关条件的自动启动适用同样规则。

模拟事件不得创建真实目录、上传真实 NAS 或调用生产回写。测试使用注入的临时目录、假飞书客户端和明确的非生产操作记录；真实测试表的受控端到端验证是另一条显式流程。

### 4.2 待办模型和有限重试

每个回写时机形成不可变意图：来源任务/运行、课程、阶段、配置版本、目标字段及选项 ID、目标文本、预期原值、记录内序号、幂等键、尝试次数和安全错误码。禁止允许客户端携带任意 Base/记录/字段直接穿透 Bridge 写接口；必须核验可信来源与已保存快照。

建议状态集合：`pending`、`processing`、`retry_wait`、`succeeded`、`superseded`、`conflict`、`dead_letter`。worker 使用数据库租约，宕机后恢复过期租约；瞬时网络错误和限流有限退避，永久字段错误/权限错误形成可操作故障。重试参数有上限，并保留所有未成功意图，不无限重放。

同记录内串行处理。更高轮次/更晚业务时机取代同一目标字段的旧意图；完成状态不能被延迟的处理中回写覆盖。较早任务结束时也不能把新轮次的字段覆盖为旧完成值。无冲突的不同字段意图仍可执行；课程路径是独立一次性意图，不因状态轮次变化丢失。

轮次不能用 outbox 插入顺序代替：真实运行启动事务为该记录分配单调 `runGeneration`，处理中和完成意图都携带同一运行代号及各自时机顺序；新的运行即使尚未产生完成意图，也已在它将要写的字段登记代号。发出更新前按 `(runGeneration, eventRank)` 比较每个字段，旧运行后完成不会因排队时间更晚而变成新状态。一次性课程路径使用独立版本域。

记录序号只能保证本机已经接收并登记的执行顺序，不声称能还原飞书所有延迟事件的真实时间顺序。现有晚到离开事件可能归档新一轮 `todo` 的限制仍需在文档中保留。

发送前重新读取当前字段：当前值已等于目标值则确认幂等成功；值仍属于预期前值或由本机已确认的上一条意图写入的值时才继续；人工已改为其他值则标记冲突。多字段规则中任何目标字段冲突时整组暂停，避免用户看到半组被主动更新；API 的实际原子性以官方契约和测试为准。响应不明时读取各目标字段核对后再决定重试。

预读与飞书更新之间不是原子比较交换，仍可能发生人工并发修改；不能宣称绝对无覆盖或 exactly-once。UI 保留最后读取/回写时间、冲突状态和重新检查入口。

本机租约和代号也不能撤回已经到达飞书的 HTTP 请求。响应超时的操作先进入结果核对，不直接让同记录的新赋值越过未知请求；重启/网络延迟下远端实际提交顺序仍须列为非原子 API 的限制，不能把本机顺序保证描述成远端绝对顺序。

### 4.3 防止回写反向触发任务

应用配置时，对同一 Base/表所有生效流程校验写入规则：回写到某字段的目标选项，不得等于该字段上任何已启用剪辑阶段的进入选项，也不得等于启用的 `00成片` 进入选项。拒绝原因应定位到具体规则。

剪辑进入条件和 `00成片` 进入条件也不得占用同一字段的同一选项；不靠配置顺序决定两个不同副作用。允许同字段使用不同选项，也允许不同字段各自配置。

回写离开剪辑触发选项时仍遵守只归档 `todo` 的规则：正在执行的任务不能被归档。需要集成用例证明处理中回写不会中止自身任务。Bridge 仍处理 SDK 投递的变更事件，不靠忽略所有机器人事件来掩盖循环。

应用新版触发规则时还要检查尚未结束任务的冻结回写规则、待重试和正在发送的意图，不能把它们的目标值新配置成触发选项。发送前按当前活动规则再次检查；冲突时保留旧快照并阻断这次写入，不偷偷改写成新规则。活动规则变更与发送许可使用同一记录/表范围的版本栅栏协调，避免两端各自验证后交叉提交。

### 4.4 飞书 API 适配确认

持久化使用字段 ID 和选项 ID，发送前确认它们仍存在。实际官方 API 对字段键、单选值采用名称还是 ID，必须在实现第一阶段通过 SDK 类型、官方文档及隔离测试表验证后，统一放入适配器；本文不假定 option ID 可直接作为 wire value。

只能更新指定已有字段，不创建字段或选项。若 API 会将未知选项名称自动建为新选项，适配器必须先验证并采用受支持的防创建策略；不能仅凭一次缓存校验声称绝对不会新增。若平台无原子保护，明确元数据检查与并发改名的限制，以测试证明常规路径不会新增。

## 5. 拟新增数据契约及模块职责

以下为设计契约，现有代码尚不包含这些结构；实施计划使用同样的业务边界，具体导出函数在各实现任务中列出。

| 数据 | 必须持久化的内容与约束 |
| --- | --- |
| 学科目录策略 | 单一总路径、课程命名字段 ID/复用选择、上传开关、路径回写目标文本字段 ID |
| 阶段回写快照 | 每阶段两个事件的规则数组；规则只含已有字段与选项 ID 及展示名称快照 |
| 额外触发快照 | 启用、字段 ID、选项 ID、固定目录名 `00成片`、配置版本 |
| 课程绑定 | 唯一记录键、唯一规范化目标目录、原始名称、实际根/课程路径、UNC/显示路径、首次绑定版本/时间 |
| 运行产物 | task/run、精确 `packageZipPath`、已登记 artifact ID、单一 ZIP 上传结果；当前协议一 run 一制品，禁止通过目录扫描或额外上传行推断产物 |
| 文件发布结果 | 绑定/run/artifact、目标完整路径、哈希、成功时间 |
| 回写待办 | 幂等键、记录序号、事件类型、来源快照、每字段预期值与目标值、状态、租约、有限重试信息 |
| 目录操作 | 唯一事件/规则键、绑定、可信来源、状态、租约、重试信息及结果；不依赖剪辑任务存在 |
| 包资源配置 | `resourceGroups`，本机调度器共享命名空间中的独占资源名称列表 |

沿用 `database.mjs` 的迁移和事务管理；新路径解析、回写客户端及 worker 各自拆成职责单一的模块。不能把持久化业务操作只挂在 SSE 通知回调上。

Bridge 的记录读取扩展到课程字段和回写预读；事件分流扩展到独立目录触发。所有失败只向 HTTP/日志暴露安全错误码，不输出凭据或飞书完整响应对象。

Taskboard 调用 Bridge 的更新请求仅传不可变操作 ID、当前 claim token 和操作版本。Bridge 通过带本机 secret 的 Taskboard 内部上下文接口解析权威意图：核验真实 Bridge 来源、运行事实、未过期租约、当前字段代号、绑定和冻结配置，返回受控目标及赋值。请求正文不能自行指定任意记录或赋值；只有拿到当前有效发送许可后才调用 SDK。该上下文接口不返回飞书应用密钥。

## 6. 配置界面

### 6.1 页面结构

左侧学科列表，右侧当前学科配置。学科点击始终切换编辑对象；“查看任务”是单独入口。右侧占用配置页面可用高度，标题和操作条固定在编辑区边缘，中间主要内容只保留一层纵向滚动。窄屏把学科选择和分区导航换行，不横向截断控件。

五个分区：

| 分区 | 内容 |
| --- | --- |
| 基础与执行 | 飞书 Base/子表、Auto-Cut 包、手动/自动模式、本机自动开关的当前约束、命名字段与包继承摘要 |
| 素材与阶段 | 初稿/初审修改/终审修改启用；每阶段独立的进入选项、视频来源、音频来源、意见来源和 ZIP 命名后缀 |
| 存储与目录 | 上传总路径、课程命名、三个固定阶段目录、实际路径和飞书回写值预览、路径检查 |
| 飞书回写 | 各阶段“处理中/本 run ZIP 上传成功”多行规则、课程路径文本字段及首次 ZIP 时机 |
| 额外触发 | `00成片` 单选触发配置、目录操作结果入口 |

不显示流程名称/说明编辑器，也不保留全局标签编辑入口。固定标签和固定说明继续对应原内部阶段 ID；旧自定义标签数据可留库，但所有显示层停止应用隐藏覆盖值。

### 6.2 草稿、应用和校验

顶部同时显示“当前生效 vN”和“草稿已保存/有未保存修改/有未应用修改”，不能用单个“草稿”标签掩盖旧版本仍在运行。底部动作固定为“保存草稿”“应用并启用”“停用当前运行配置”。应用失败保持旧活动版本，保存草稿不改变活动配置。

允许保存未完成草稿，但仍拒绝非法结构、超限输入和不安全值；缺少业务必填项仅在应用时阻止启用。停用阶段保留原值，折叠成摘要，不参与启用阶段的业务校验。使用原声时隐藏不适用的外部音频设置。

切换学科保留本次编辑会话中的各学科草稿；关闭/离开存在未保存修改时提示保存或放弃。字段旁显示错误，页签显示数量，操作条提供错误跳转。错误不能只存在于禁用按钮的悬浮提示中。

字段/选项和包各有刷新入口。区分“加载中”“加载失败可重试”“成功但为空”“旧选择已不存在”。刷新保留编辑值，并标识失效选择；不因为网络失败清空配置或假报包已被删除。

### 6.3 路径检查与运行结果

实时示例预览不访问 NAS、不创建目录。显式“检查路径”可只读检查根目录存在、映射和格式；不能以只读存在性检查声称有写权限。“写入测试”明确会在所选根目录创建并清理专用测试文件/目录，使用独立随机名称，绝不清理已有课程目录；草图按钮仅模拟显示状态。

任务详情分开显示剪辑结果、单个 ZIP 的登记/上传状态、状态回写、课程路径回写。一个 run 的 ZIP 未成功发布时不能显示该 run 已完成；上传成功但回写失败时，ZIP 仍显示成功，回写单独显示待重试。按钮按失败项提供“重试上传”“重试状态回写”“重试路径回写”，不得用重新剪辑来修复回写失败。

额外触发有独立目录操作记录：课程、触发时间、目录、成功/等待重试/失败、错误说明和定向重试。目录成功不显示虚构的剪辑任务。

## 7. Auto-Cut 包与旧配置迁移

### 7.1 配置归属

包拥有工作区、固定 prompt、模型、ZIP 来源目录、并发上限及“独占资源（可选）”。学科引用包并显示继承值；不再出现可冲突的第二个 ZIP 来源目录输入。现有后端包来源与学科来源必须一致的检查需改为校验解析后的单一来源，不能只隐藏前端字段。

普通学科配置移除并发组、并发上限、资源组。调度组固定为 `autocut:<alias>`。独占资源在同一台 Taskboard 内共享命名空间，同名资源在不同包间也互斥；不声称可以锁住其他电脑或外部软件。

保留现有阶段运行安全上限：同一包的阶段执行最多 1 个。包最大并发继续作为现有调度约束，界面显示“阶段任务实际并发 1”；不因移动配置而意外开放并行。

新任务登记时冻结包资源列表；已排队/执行任务使用原有资源快照。现有包并发上限的实时约束语义继续保留，不能把迁移误实现为所有调度参数都改成快照。

### 7.2 迁移规则

升级不自动应用新草稿，不改已排队/正在执行的上传路径和任务快照。旧活动快照在明确应用新版配置前走兼容路径；新能力默认关闭。数据库迁移只新增结构并保留旧值，不能通过删状态文件迁移。

旧阶段目标路径只有在可无歧义转换为同一总路径时给出迁移预填；不同根或含课程/阶段私有路径时标记“需要选择上传总路径”，允许保存草稿，不能猜测共同祖先并启用。已交付的旧课程目录不自动搬迁或补绑定。

旧学科资源锁非空时，把同包所有旧资源取并集作为包迁移候选，明确列出来源供检查；保留旧任务锁。无法安全应用候选时阻止新版应用并提供到包配置的入口，不能因隐藏字段而丢锁。旧自定义并发组关系也必须检测；若跨包共用旧组，保留兼容调度直至转换为可验证的包独占资源约束，不能无提示解除互斥。

旧学科 ZIP 来源与包来源相同可直接收敛；仅旧学科有来源或同包多个学科来源不同，先显示迁移冲突，选择/拆分包后才能应用新版。旧配置继续可读，不自动改真实包 registry。
