# 剪辑包配置模板与小学化学成片流程设计草案

日期：2026-10-09。状态：包身份与配置草稿已实施；剪辑执行与附件交付仍为设计草案。

本文记录已确认的产品方向、待补充的接口和建议开发顺序，不替代本仓库的运行规范。运行边界仍以根目录 `AGENTS.md` 为准。

当前已实现固定 `workflowTemplate` 身份、manifest 校验、包 registry/API、ZIP 与 VM 的独立配置草稿及保存版本检查。草稿按学科、包别名、模板 ID 和版本隔离；ZIP 的启用使用学科全局递增版本，同步失败保留原活动配置。旧包未声明时解析为 `document_draft_zip` v1。新模板 `vm_pmo_review_video` v1 只能预览/保存，启用及受控执行仍被阻断。详细保存与启用规则见 [按剪辑包保存流程配置](2026-10-12-package-workflow-profiles-design.md)。

可使用 [VM 配置预览示例](../../../examples/vm-pmo-review-video-preview) 检查与保存新包；示例无嵌入运行时或 plan/render。独立审批 CLI 已实现，但尚未绑定 Taskboard task/run；审核轮次、实际剪辑、成片交付和 PMO 上传/回写均未接通。

## 1. 已确认的需求

- 在同一编排器中，不同学科可以选择不同剪辑包，面板显示该包对应的内置配置模板。
- 现有 Auto-Cut-Lite 保留当前的文档/附件来源、三阶段配置和剪映草稿 ZIP 交付。
- 小学化学需要开发一个新剪辑包：根据 PMO 的原视频 vmid 获取素材，结合保留时间段、审核文字和截图进行剪辑，输出审核 MP4。
- 首次剪辑按原视频时间轴和填写顺序拼接；后续审核修改基于上一轮明确绑定的审核成片，不再次套用历史首剪时间段。
- 只写“剪掉某几个字”时，默认删除对应音画、缩短视频；明确只去声音／停顿占位时，保留画面和时长。
- 审核 MP4 作为附件上传到同一 PMO 记录，建议目标为已存在的“视频成片审核”附件字段；实际绑定以实时字段元数据为准。
- 新剪辑执行包尚未实现；当前提供无执行器的配置预览示例。模板与草稿功能不会自动变更本机包 registry、学科活动配置或生产数据。

## 2. 建议顺序：接口 → 剪辑包最小版本 → 编排器配置与交付 → 测试表联调

先明确双方输入、输出和完成条件，再开发剪辑包的最小可运行版本。包的真实能力稳定后，配置面板和执行适配按同一合同对接。

面板可以在接口确定后使用 fixture 并行开发，但正式配置项与执行资格必须以经过验证的包能力为准。配置面板本身不能证明视频已经正确剪辑或具备自动下载权限。

### M0：冻结第一版接口

交付物是版本化接口说明和离线输入/输出 fixture。当前接口草案见 [VM / PMO 审核成片接口草案](2026-10-09-vm-pmo-review-video-interface-draft.md)；模板身份部分已实现，plan/render、运行绑定和附件交付合同仍待验收与冻结：

| 内容 | 第一版约定 |
| --- | --- |
| 工作流模板 | 已实现内置旧模板 `document_draft_zip` v1 与预览模板 `vm_pmo_review_video` v1，不使用包展示名称或版本号判断界面。 |
| 运行身份 | 绑定 task、run、Base、table、record、subject config version 和 stage；新输入合同与旧 v1 合同明确区分。 |
| 输入 | 原视频 vmid、已批准取得的素材、本轮字段和截图快照；首剪区间基于原视频，审核操作基于明确绑定的上一轮成片。 |
| 剪辑计划 | 结构化记录操作、依据、区间顺序和需确认项；含糊或冲突的意见进入待确认。 |
| 输出 | 本次运行精确绑定的 MP4、SHA-256、大小、时长、编码和验收结果；失败回执使用稳定错误码。 |
| 成功条件 | 成片通过校验，媒体上传完成，返回的附件 token 已绑定到目标 PMO 记录的指定附件字段并确认。 |

明确“任务绑定及制品回执”和“PMO 字段业务内容”的职责：单元格只提供受控业务值，不提供命令、prompt、工作区路径或平台凭据。

### M1：新剪辑包离线最小版本

第一轮使用已取得的本地测试视频和固定意见 fixture，验证：

1. 按原视频时间轴保留一个或多个片段，按计划顺序拼接。
2. 支持删音画、局部静音和受限的等时长画面替换，默认保留其他原音，导出可播放的 MP4；确定性媒体处理可采用 FFmpeg。
3. 校验时间范围、目标时长、音视频流和输出文件，生成绑定本次运行的回执。
4. 文字和截图先形成可核对的计划，包含时间字段括号内的要求。字词与残留帧必须结合实际素材定位；未实现或含糊的修改明确显示待确认/不支持，不能仅接收输入后声称已执行。
5. 输出错误可诊断，重试使用新的运行身份，不扫描“最新文件”。
6. 覆盖上一轮成片审核和历史附件的明确导入，不按文件名或附件次序选择 parent，也不重复消费已完成的意见。

此里程碑先证明剪辑和输出能力。VM 的生产下载审批以及真实 PMO 附件发布由后续集成验证。

### M2：编排器模板、持久化和执行适配

包通过受校验的 `PACKAGE-MANIFEST.json.interface.workflowTemplate` 选择编排器内置模板；包名称、包版本继续沿用现有插件身份读取方式。身份读取、registry/API、独立 ZIP/VM 草稿及 ZIP 活动版本切换已实现；VM 活动版本和真实执行适配仍是后续要求。

包只声明模板与协议能力，不提供可执行的界面代码或任意表单 schema。显式未知模板/版本应拒绝启用。缺少声明的历史包按照现有旧合同兼容读取；不能把新包声明错误静默当作旧包。

当前保存会重新读取可用 workspace 的真实 manifest，API 省略模板仍会识别 VM；已有别名不能改变模板。VM 草稿无需 ZIP 目录或模型，但不能启用。草稿 API 按当前学科元数据校验文本、附件、单选字段和选项，允许未填写字段保持空值；保存采用独立 revision，不消费学科活动配置版本。它尚未产生能交给 Bridge 的 VM 活动快照。

面板组织建议：

| 旧模板 | 新模板 |
| --- | --- |
| 基础与执行 | 基础与执行 |
| 素材与阶段 | VM 素材与剪辑意见 |
| 存储与目录 | 成片与交付 |
| 飞书回写 | 飞书回写 |

新模板绑定以下实际字段类型：

| 字段用途 | 已知字段名称 | 校验 |
| --- | --- | --- |
| 素材标识 | 原视频vmid | 单一非空文本，格式由下载接口合同定义 |
| 首剪要求 | 剪辑保留片段的时间点 （可由多个片段拼到一起） | 文本，转换为有序区间并验证原视频时长，同时提取括号内的剪辑操作 |
| 审核文字 | 审核意见 | 文本 |
| 审核截图 | 审核意见截图说明 | 附件，按本次运行绑定取得图片 |
| 审核成片 | 视频成片审核 | 已存在且可写的附件字段 |
| 触发及回写 | 配置选定的状态字段 | 已存在的单选字段及选项 |

配置保存原则：

- 每个学科独立保存配置；按学科、包别名和模板身份保留可恢复的配置档案。同模板兼容升级采用明确的版本迁移规则，不按包名称猜测。
- 切包只改变当前编辑对象，切回恢复对应草稿及面板中暂存的未保存修改。切包后离开页面应提示未保存内容，不能静默覆盖原配置。
- 保存草稿不替换 Bridge 当前活动版本；启用才校验并应用。同步失败保留原活动配置。
- 继续使用学科全局递增的配置版本，避免切换配置档案后复用已存在的活动版本号。
- 活动快照只包含当前选择的包、模板和配置。历史任务冻结自己的包、模板、字段、阶段及版本；“刷新包”不得把旧任务换到不同模板合同。
- 表单可编辑不等于执行已支持。未完成执行适配的模板可以预览/保存草稿，启用时明确阻断，不落入旧 ZIP runner。
- 多阶段继续使用现有固定阶段身份，支持逐阶段启停及配置；首轮仅启用经验证的阶段。不同阶段的素材和意见不隐式共用。

当前主要落点：

- 包声明读取：`taskboard/server/feishu-package-identity.mjs`。
- 包 registry 与 API：`taskboard/server/feishu-package-config.mjs`、`feishu-package-api.mjs`，以及 Bridge 的 `src/package-config.mjs`。
- 面板与类型：`taskboard/web/src/components/FeishuWorkflowPanel.tsx`、`FeishuStageEditor.tsx`、`types.ts`、`api.ts`。
- 学科草稿、活动版本与共享配置：`taskboard/server/feishu-workflow-store.mjs`、Bridge 的 `src/workflow-config.mjs`。
- 运行输入与执行：`feishu-run-inputs.mjs`、`feishu-source-manifest.mjs`、受控执行协调器与包专属 runner 适配。

### M3：VM 获取素材、PMO 附件交付及真实联调

已通过网页只读检查确认：VM 可以按 PMO 的原视频 vmid 唯一定位素材；当前账号的“下载”和“获取链接”都进入申请表，页面说明经飞书审批后把地址发送至申请人邮箱。

用户提供的《【生产环境】上传视频自动化说明》只有验证码、文件上传、创建制作任务和按任务 ID 查询状态的流程，没有按 vmid 获取下载地址的合同，不能据此实现自动下载。

独立 `vm-approval.mjs` 已按当前 Shadow 前端契约实现正常 SSO、持久化申请意图、审批查询及获批领取，明确要求 `APPROVED`、精确 VMID 和制作完成，不依赖邮箱。已验证真实后台申请、获批 720p 素材下载，以及新 CLI 对既有申请和精确回执的接管复核；新 worker 的全新申请到首次下载尚待真实整链路验收。接口不是正式稳定外部契约，初次/重启后仍需登录，长期自动续期未实现。详见 [VM 素材采集验证](../../vm-source-acquisition.md)。

下一步是将独立审批状态绑定到受控 Taskboard task/run、素材及本轮输入，随后接入经过离线验证的剪辑包；不能从当前独立 CLI 或草稿表单推断生产自动执行已经可用。

新附件交付使用独立的持久化状态：

`MP4 已验证 → 媒体已上传 → 附件字段已绑定并确认 → 交付完成 → 阶段完成回写`

- 媒体上传成功后持久化附件 token；绑定失败优先复用该 token。
- 上传/绑定失败只重试交付，不重新剪辑。导出后释放剪辑资源，交付独立排队。
- 按运行身份与目标字段去重并持久化租约和重试状态，保留已有附件及人工更新；追加策略不等于允许每次重试追加重复附件。
- 上传响应丢失等不确定结果需记录并受控恢复，整体仍为至少一次语义。
- 当前旧路径在 ZIP 验证后置任务完成，旧上传入队又要求任务完成。新附件模式应建立独立的交付入队条件，避免“等待完成才能上传、等待上传才能完成”的循环。

## 3. 兼容、权限及验收

旧版 ZIP manifest、result、receipt、准确路径、哈希、NAS 发布和课程目录回写仍由旧模板负责；新模板采用独立版本化合同和 MP4 完成门禁。

接入真实执行前，须同步增补根目录 `AGENTS.md` 中新附件分支的完成条件及模拟来源限制，保留现有 ZIP 分支的明确约束，并更新 README、接口合同和自动化测试。

验收至少覆盖：

- 旧学科和历史配置不需要重填，旧任务仍能使用其冻结合同。
- 同学科旧包→新包→旧包可恢复配置；刷新/重启后仍保留；两个学科选择同包也不串参数。
- 未保存切包、草稿保存、启用失败和 Bridge 同步失败不替换原活动版本。
- 未知模板、协议不兼容、缺失/错类型字段及失效选项不能启用执行。
- 裁剪拼接、区间越界、意见冲突、截图解析失败和 MP4 验收失败有明确结果。
- 媒体上传失败、绑定失败、响应丢失及重启恢复不重复剪辑，不覆盖其他附件，不提前写审核完成状态。
- 模拟事件、普通任务、伪造标签不能下载生产素材、执行剪辑、上传媒体、绑定附件或回写飞书。
- loopback、Bridge 专用登记、显式自动执行开关、活动 automatic 配置和本机包白名单保持原边界。

开发与验证在当前功能分支进行；测试使用离线 fixture 和独立测试表/示例项目。通过适当测试和代码评审后，再进行合并及部署。
