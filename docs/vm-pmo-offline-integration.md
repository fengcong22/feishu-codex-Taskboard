# VM / PMO 离线联调

Taskboard 已接入 `auto-cut-slicing` 的独立 VM 初稿运行时：可信 Bridge 登记任务 → 绑定审批下载队列 → 冻结本轮输入 → `plan/render` → 校验唯一 MP4 → 上传 PMO 附件并读回 → 阶段完成回写。首版只允许 `initial`、单选状态触发、明确保留时间范围；审核修改、parent 轮次和 NAS 成片归档仍不可启用。自动化验证与真实测试表验收分别记录，代码接通本身不代表真实审批、上传链路已经验收。

以下离线联调脚本仍只生成合成媒体，调用真实剪辑包，再由 Taskboard 校验计划、回执和 MP4。它不启动 Bridge、提交审批、读取生产视频或写入 PMO。

## 运行

需要 Node.js、Python 3.10–3.12，以及包含 `libx264` 的 FFmpeg/ffprobe；两个媒体工具须在 PATH 中。从本仓库运行，使用剪辑包工作区及 Python 可执行文件的规范绝对路径：

```powershell
node scripts/check-vm-pmo-offline.mjs --package-root 'E:\codex\Auto-cut-slicing-src' --python 'C:\Users\YC\AppData\Local\Programs\Python\Python311\python.exe'
```

每次检查创建独立的 `.runtime/vm-pmo-offline/run-*` 目录，包含合成源视频、各用例的输入/计划/回执、成功用例的 MP4，以及 `verification.json`。这些文件被 Git 忽略。源视频位于独立采集目录，各运行共用源文件，不复制到每轮目录。退出码为 0 才表示本次全部检查通过；生成过 MP4 本身不是通过凭据。

脚本验证有序范围拼接与带原音的 H.264/AAC、1920×1080、25 fps 成片；独立全量解码、哈希与音视频轨时间覆盖验收；拒绝旧回执、被修改的输入/计划/成片、其他 run 的回执、引用外部媒体的伪装 MP4 和几乎空的音轨。语义意见、多条意见及审核阶段返回合法 `blocked` 并保留全部原文。

## 接口与边界

入口固定为 `python -m auto_cut_slicing.vm_pmo plan --input ... --context ...` 和 `render --input ... --context ... --plan ...`。完整 v1 字段与错误码维护在剪辑包的 `docs/vm-pmo-offline-contract-v1.md`；两侧读取同一份文件完成联调。当前包身份为 `auto-cut-slicing` `0.2.0`，协议为 `vm_pmo_review_video` / schema 1。

首版执行范围是 `initial`、无 parent、单个本机源视频、一条当前轮意见中的明确保留时间范围、唯一 MP4。按原文顺序拼接；任何额外语音、画面、删词、静音或静帧要求均阻断，不忽略后继续。首次初稿以 `vm_original` 时间轴解释；审核 parent、上一轮成片时间轴和带证据编辑尚未实现。

受信 context 指定所有路径。input/context 固定在本轮目录，计划、回执和输出不得越出本轮目录；源可在独立本机目录。文件须为普通单链接文件，路径不得经过符号链接或目录别名。输入、源、计划均按实际文件字节绑定。VM 源固定以 MOV/MP4 解析、仅允许本机 file 协议并关闭外部数据引用，不能由清单引入未绑定的素材。

`runVmPmoOffline` 使用固定模块及 argv，剥离飞书、Shadow 等凭据环境和 Python 注入变量，支持超时和中断。它保留启动前 context/input/source 的内存快照；render 还冻结已批准计划及回执。子进程结束后必须与原快照一致，不能通过改写 context 重新绑定任务。合法 `blocked` 退出 0 并停止该轮；进程失败、超时或异常回执不能登记成功。

宿主独立检查身份、文件摘要、唯一输出、媒体格式、帧率、音视频轨起点和时长，并执行完整解码及验收前后的摘要校验。`rendered` 仅表示本机成片验收通过，不代表 PMO 上传或人工语义验收完成。

## 本机启用与测试表验收

在被 Git 忽略的 `.env.local` 设置 `CODEX_VM_PMO_PYTHON_PATH` 为上述 Python 的规范绝对路径。可选 `CODEX_VM_PMO_RUN_ROOT` 指定本轮文件根目录；默认使用 Taskboard 数据目录下的 `vm-pmo-runs`。Python、包工作区、manifest、固定模块和路径检查未通过时，VM 能力保持不可用。检查本机能力不会初始化审批、连接飞书或创建运行目录。包启用跳过 Codex 模型设置，执行器固定为本机 Python 模块。

在包管理验证真实剪辑包并启用，然后在测试学科选择该包，绑定 VMID、共同命名、初稿意见、单选触发项、MP4 附件目标，以及开始/完成的单选回写。填写申请部门和原因，关闭审核修改与成片归档，保存草稿并启用。启用仍实时校验字段、选项、包身份及 Bridge 同步；仅有声明的预览包不能执行。Bridge 宿主显式允许已启用、manifest 一致的 VM registry；旧 ZIP 路由及通用执行入口继续拒绝 VM 包。

通过“本机设置 → VM 下载”连接正常 Shadow 账号，核对本机素材根目录，并开启“允许本机自动剪辑”。按根 `AGENTS.md` 停止、重新启动服务，使用 `check-local.ps1 -RequireFeishu` 验证官方 SDK 监听。保存或启用配置不会补跑现有触发状态；只对指定测试记录受控地离开触发项、再进入触发项，观察该次真实事件。

任务、来源、配置与包快照、本次自动预约意图在同一数据库事务中持久化，任一步失败全部回滚。审批等待不占剪辑槽；下载使用同一队列的精确申请指纹与获批采集回执，不能通过改数据库或复制源文件伪造审批事实。关闭开关取消未开始预约，重新开启不补历史；已经真实开始的运行继续交付。重启恢复冻结的策略和输入，状态不明的进程只核对已有回执，不盲目重新渲染。VMID、命名、初稿意见、触发状态或包身份在执行前发生变化时，该轮阻断。

“剪辑中”只在实际 render 子进程启动后回写；上传得到 token 后还须把同一个 MP4 绑定到配置附件字段并读回确认，才能回写阶段完成。上传结果不明时保留异常状态，不盲目重传。附件字段已有其他文件时阻断。飞书附件更新接口不提供条件写入（CAS），即使写前重复读取，读取和写入之间仍有人工作业竞态；首轮测试应避免同时编辑目标附件字段。普通任务、模拟来源和伪造描述均不能申请、渲染、上传或回写。

真实审批尚未批准时，任务保持等待，需由正常审批人批准后继续。首轮建议 `00:00–00:20`；上传后的 MP4 仍需人工试听观看。审核 parent、轮次和 NAS 发布将另行实现，旧 ZIP 完成条件保持独立。
