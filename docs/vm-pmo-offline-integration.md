# VM / PMO 离线联调

Taskboard 已接入 `auto-cut-slicing` 的 VM/PMO v2 流程：可信 Bridge 登记任务 → 初稿绑定正常审批下载，审核绑定上一轮已确认交付的 MP4 → 冻结本轮输入 → `plan/render` → 校验唯一 MP4 → 追加到 PMO 附件并读回 → 阶段完成回写。配置可分别启用 `initial` 和 `review`；审核要求包 manifest 声明 v2 driver，不重新申请 VM 下载。Taskboard 原样冻结并传递修改意见，由剪辑包解释意见、生成时间线操作及词级证据；初稿支持明确保留区间，v2 还支持有源哈希的语音删词、静音和 cue。匹配含糊或证据不全时由剪辑包在渲染前阻断。Taskboard 校验任务、输入与回执绑定、计划结构和最终 MP4，不重新解析意见或推导剪辑操作。成片 NAS 归档是独立可选 worker。自动化验证通过不代表真实测试表的审批、附件读回或归档验收已经完成。

以下离线联调脚本仍只生成合成媒体，调用真实剪辑包，再由 Taskboard 校验回执绑定、计划结构和 MP4。意见解释、对齐和操作生成由剪辑包完成。它不启动 Bridge、提交审批、读取生产视频或写入 PMO。

## 运行

需要 Node.js、Python 3.10–3.12，以及包含 `libx264` 的 FFmpeg/ffprobe；两个媒体工具须在 PATH 中。从本仓库运行，使用剪辑包工作区及 Python 可执行文件的规范绝对路径：

```powershell
node scripts/check-vm-pmo-offline.mjs --package-root 'E:\codex\Auto-cut-slicing-src' --python 'C:\Users\YC\AppData\Local\Programs\Python\Python311\python.exe'
```

每次检查创建独立的 `.runtime/vm-pmo-offline/run-*` 目录，包含合成源视频、各用例的输入/计划/回执、成功用例的 MP4，以及 `verification.json`。这些文件被 Git 忽略。源视频位于独立采集目录，各运行共用源文件，不复制到每轮目录。退出码为 0 才表示本次全部检查通过；生成过 MP4 本身不是通过凭据。

脚本用合成媒体调用真实剪辑包和 Taskboard 校验器，验证 v1 范围编辑及 v2 父片删词、唯一词起点 cue、连续两轮复用、ASR 源哈希绑定、重复词歧义阻断；还独立验证 H.264/AAC、1920×1080、25 fps、全量解码、时长和哈希。被修改的输入/计划/成片、其他 run 的回执、伪装媒体和几乎空的音轨均会被拒绝。离线脚本只在 `.runtime/vm-pmo-offline` 下生成合成源、对齐、计划和成片，不调用审批、飞书上传、PMO 回写或归档目标。

## 接口与边界

入口固定为 `python -m auto_cut_slicing.vm_pmo plan --input ... --context ...` 和 `render --input ... --context ... --plan ...`。当前包身份为 `auto-cut-slicing` `0.3.0`。可执行包在初稿和审核阶段均须显式声明 `vm_pmo_review_video` contract v2 与固定 `vm_pmo_review_video_v2` driver，并发送 schema v2。历史 schema v1 输入与回执仍可读取和离线校验，但不再授权新的 v1 自动执行。字段、计划与错误码分别见剪辑包的 [v1 契约](../../Auto-cut-slicing-src/docs/vm-pmo-offline-contract-v1.md) 和 [v2 契约](../../Auto-cut-slicing-src/docs/vm-pmo-offline-contract-v2.md)。

v1 保持 `initial`、无 parent、`vm_original` 时间轴和明确保留区间。v2 初稿也使用无 parent 的原 VM 源；v2 `review` 必须绑定 Taskboard 管理且读回交付成功的上一轮 MP4，所有区间和词语都按该父片时间轴解释。当前一轮最多冻结一条原始意见；范围、词级删词/静音、完整词 cue 和有明确 source-bound visual evidence 的静帧按协议执行，未知操作不忽略后续继续，而是阻断整轮。词级操作使用剪辑包本机配置的 ASR 生成一次对齐文件；重复词匹配、缺失/过期对齐或保护词冲突都会阻断，render 重试复用同一份源哈希绑定的对齐和计划。

审核起点 cue 的锚点、搜索范围、唯一词匹配及时间戳由剪辑包依据冻结意见和源片生成；Taskboard 保留并转交原始意见，校验计划与本轮输入和包回执的绑定，不自行判断 cue 或删词是否符合意见。Taskboard 仍独立验证 MP4 的摘要、格式、帧率、音视频轨及全量解码。阶段回写重试会检查该记录最新登记的 VM 阶段任务仍对应当前轮次，Bridge 写入前还会重新读取阶段状态；新阶段或新审核轮登记后，旧轮次会记为冲突，不覆盖新阶段。飞书没有条件更新接口，Bridge 最后一次读取与写入之间仍存在人工并发编辑窗口。

受信 context 指定所有路径。input/context 固定在本轮目录，计划、回执和输出不得越出本轮目录；源可在独立本机目录。文件须为普通单链接文件，路径不得经过符号链接或目录别名。输入、源、计划均按实际文件字节绑定。VM 源固定以 MOV/MP4 解析、仅允许本机 file 协议并关闭外部数据引用，不能由清单引入未绑定的素材。

`runVmPmoOffline` 使用固定模块及 argv，剥离飞书、Shadow 等凭据环境和 Python 注入变量，支持超时和中断。它保留启动前 context/input/source 的内存快照；render 还冻结已批准计划及回执。子进程结束后必须与原快照一致，不能通过改写 context 重新绑定任务。合法 `blocked` 退出 0 并停止该轮；进程失败、超时或异常回执不能登记成功。

宿主独立检查身份、文件摘要、唯一输出、媒体格式、帧率、音视频轨起点和时长，并执行完整解码及验收前后的摘要校验。`rendered` 仅表示本机成片验收通过，不代表 PMO 上传或人工语义验收完成。

## 本机启用与测试表验收

在被 Git 忽略的 `.env.local` 设置 `CODEX_VM_PMO_PYTHON_PATH` 为上述 Python 的规范绝对路径。可选 `CODEX_VM_PMO_RUN_ROOT` 指定本轮文件根目录；默认使用 Taskboard 数据目录下的 `vm-pmo-runs`。Python、包工作区、manifest、固定模块和路径检查未通过时，VM 能力保持不可用。检查本机能力不会初始化审批、连接飞书或创建运行目录。包启用跳过 Codex 模型设置，执行器固定为本机 Python 模块。

在包管理验证并启用真实 `auto-cut-slicing` 包，然后在测试学科选择该包，绑定 VMID、共同命名、初稿意见、初稿单选触发项、MP4 附件目标，以及开始/完成回写。填写申请部门和原因。需要审核时，再绑定审核意见、可选意见附件、不同的审核触发项及该阶段回写；激活时重新核对每个启用阶段的实时字段和选项；即使只启用初稿，也要求 manifest 的 v2 contract 与固定 driver 一致。成片归档可以单独配置，不属于审核启用的必需条件；它不能与编辑阶段共用触发选项。只有完整字段、包身份、Python runtime 和 Bridge 同步全部通过后才能启用，纯声明预览包仍不可执行；旧 ZIP 路由及通用执行入口继续拒绝 VM 包。

通过“本机设置 → VM 下载”连接正常 Shadow 账号，核对本机素材根目录，并开启“允许本机自动剪辑”。按根 `AGENTS.md` 停止、重新启动服务，使用 `check-local.ps1 -RequireFeishu` 验证官方 SDK 监听。保存或启用配置不会补跑现有触发状态；只对指定测试记录受控地离开触发项、再进入触发项，观察该次真实事件。

任务、来源、配置与包快照、本次自动预约意图在同一数据库事务中持久化，任一步失败全部回滚。初稿审批等待不占剪辑槽；下载使用同一队列的精确申请指纹与获批采集回执，不能通过改数据库或复制源文件伪造审批事实。审核只读取 confirmed delivery 指针指向的父片，不查询“最新附件”或申请新 VM 视频。关闭开关取消未开始预约，重新开启不补历史；已经真实开始的运行继续交付。重启恢复冻结的策略、parent SHA 和输入，状态不明的进程只核对已有回执，不盲目重新渲染。VMID、命名、阶段意见、触发状态、包身份或父片字节在执行前发生变化时，该轮阻断。

“处理中”只在实际 render 子进程启动后回写。交付队列先上传并持久化 token，再重读目标附件，保留已有附件并仅在 token 不存在时追加，最后读回确认；阶段完成回写可独立重试而不重新渲染。结果不明时保留持久状态并复核已知 token，不盲目重复上传。飞书附件更新接口不提供条件写入（CAS），读取和写入之间仍有人工作业竞态；真实联调时避免同时编辑目标附件字段。普通任务、模拟来源和伪造描述均不能申请、渲染、上传或回写。

真实审批尚未批准时，初稿任务保持等待，需由正常审批人批准后继续。首轮初稿可用 `00:00–00:20` 验证；审核测试需先完成一轮附件读回，才能由记录进入审核选项创建下一轮。每个交付 MP4 仍需人工试听观看。归档触发需使用明确的 PMO 状态边沿，worker 只读取确认交付指针，SHA 不一致或同名异内容会安全阻断。旧 ZIP 完成条件保持独立。
